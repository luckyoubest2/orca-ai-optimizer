# 虎鲸笔记 AI 优化插件：可行性分析与优化建议

> 分析基准：本机安装的 Orca Note v1.88.0（渲染主包 `out/renderer/assets/index-BXaynqXZ.js`）、
> 官方插件 API 文档（orcanote-docs）、本地插件源码（Orca-quickai、Orca-layout-manager）。
> 结论速览：**两个特性均可实现**。特性 2（对话管理 + 空对话自动清理）实现简单、价值最高，建议先做；
> 特性 1（面板按钮打开/查找该面板唤起过的 AI 对话）需要维护一张"面板 -> 对话历史"注册表，
> 并处理面板侧按钮的 DOM 细节，排二期。

---

## 一、现状核实（为什么这两个需求是真实痛点）

### 1. AI 对话的真实存储形态

AI 对话不是独立数据库记录，而是**当前文档里的 `aichat` 块**：

```js
_repr = {
  type: "aichat",
  ctx: [根块ID],      // 从哪个面板/文档打开
  msgs: [...],        // 消息数组（system / user / assistant）
  cap: "标题",         // 自动生成的对话标题（可选）
}
```

- 创建时自动打上 **"AI Result" 标签**（设置键 21，`AppKeys.AITag`，用户可改名）。
- 对话消息全部存在 `msgs` 里，块本身是普通块：可被引用、搜索、导出。
- 首次渲染时系统会把 system 提示词写入 `msgs`，所以"空对话"不等于 `msgs` 为空数组，
  更稳妥的判定是 **`msgs` 中没有 `role === "user"` 的消息**（用户从未真正提问）。

### 2. 内置 AI 按钮每次都会新建空对话（已确认）

面板侧边工具条 `.orca-block-editor-sidetools` 里已有 AI 助手按钮（`ti-message-chatbot`），
但其点击回调是：

```js
// 每次点击：新建一个空 aichat 块，再跳转过去
j0 = await invokeEditorCommand("core.editor.insertBlock", null, null, null, null,
  { type: "aichat", ctx: [当前根块], msgs: [] })
await invokeEditorCommand("core.editor.insertTag", null, j0, "AI Result")
goTo("block", { blockId: j0 })   // Shift 则 openInLastPanel
```

**结论**：内置按钮没有"继续上次对话"的能力，每点一次（哪怕马上关掉）都会留下一个空对话块。
这正是特性 1 的缺口和特性 2 中"空对话泛滥"的来源。

### 3. 已有 API 能力对照（全部可被插件调用）

| 能力 | 接口 | 说明 |
| --- | --- | --- |
| 查询对话 | `orca.invokeBackend("get-blocks-with-tags", ["AI Result"])` | 返回 `Block[]`，含 `properties`（可读 `_repr`）、`created`/`modified`、`refs` |
| 兜底查询 | `get-all-blocks` / `Query` | 标签被改或缺失时按 `_repr.type === "aichat"` 过滤 |
| 删除 | `orca.invokeBackend("delete-blocks", ids)`；编辑器内 `core.editor.deleteBlocks` | 后者可撤销；删除后广播 `orca.delete-blocks` 刷新 UI |
| 面板导航 | `orca.nav.goTo("block", {blockId}, panelId?)`、`openInLastPanel`、`findViewPanel` | 在指定面板打开某对话块 |
| 面板状态 | `orca.state.activePanel`、`panels`、`panelBackHistory` | 监听"哪个面板打开了哪个对话"，用于登记历史 |
| 持久化 | `orca.plugins.setData/getData/removeData` | 存"根块 -> 最近对话"映射 |
| 状态订阅 | `window.Valtio.subscribe(orca.state, ...)` | 监听面板、块变化（layout-manager 已验证此模式） |
| 侧边栏/UI 注入 | DOM 注入 `nav#sidebar`、`.orca-block-editor-sidetools` | layout-manager 已验证可行性 |

## 二、特性 1：面板侧按钮打开/查找"该面板唤起过的 AI 对话"

### 需求澄清

这里说的不是"按 ctx + 修改时间推断最近对话"，而是两层能力：

1. **打开上次**：点面板侧按钮，默认打开该面板**上一次唤起（打开/新建）的 AI 对话**；
2. **查找**：从同一入口能列出/搜索**这个面板唤起过的全部 AI 对话**，点选打开。

要点是"记录事实"而不是"事后推断"——谁在哪个面板唤起过哪些对话，由插件自己登记。

### 可行性：✅ 高（约 7 分/10），主要工作量在 UI 挂载与注册表维护

核心机制完全成立：对话就是带 `ctx` 的 aichat 块，"该面板上次使用的对话"可以按
**仓库 + 根块 ID**（`viewArgs.blockId`）登记和找回。

### 推荐方案

1. **"这个面板"怎么标识**（关键决策）：
   - 面板 ID 每次会话随机生成（`ShortUniqueId`，应用布局时还会整体重生成），**不能当持久化主键**；
   - 稳定标识 = **仓库 ID + 面板当前根块 ID**（`viewArgs.blockId`）。面板在显示同一个文档时，它们的
     "面板历史"自然合并；同一会话内多个面板显示同一文档时，可再用 `panelId` 做会话级细分。

2. **面板 -> 对话历史注册表**（核心）：
   - 用 `orca.plugins.setData` 持久化：`{ "repo/根块ID": [ { blockId, openedAt, title }, ... ] }`；
   - **登记时机**：
     - 插件的面板按钮被点击（打开上次 / 强制新建）时；
     - 用户在面板历史列表中打开某条时；
     - 订阅 `orca.state.panels` / `panelBackHistory`，面板 viewArgs 变成某个 aichat 块时（用户从别处点进来的也登记）；
   - **兜底回填**：新装插件时注册表为空，用 aichat 块的 `ctx` 包含当前根块来回填
     （内置按钮创建的对话都带 `ctx:[根块ID]`），之后以注册表为准。

3. **按钮接管**（关键点）：
   - 内置按钮的 onClick 直接调用组件回调，**不走命令系统**，所以
     `registerBeforeCommand("core.editor.openAIAssistant", ...)` 拦不到按钮点击（只能拦快捷键/菜单）。
   - 正确做法是 DOM 级接管：在 `.orca-block-editor-sidetools` 上用事件代理拦截
     `ti-message-chatbot` 按钮点击；或注入自己的按钮并隐藏内置按钮（仿 layout-manager）。
   - 面板折叠/切换时按钮会重挂，需要 MutationObserver 或订阅 `orca.state.panels` 保持状态一致。

4. **交互语义**（对齐内置习惯并保留逃生通道）：
   - 单击：打开该面板**上次唤起的对话**（校验块仍存在且非空，失效则跳到下一条，再不行就新建）；
   - 单击旁的小箭头/长按：弹出**该面板的对话历史列表**（标题、时间、消息数，带搜索框），点选打开；
   - Shift+单击：在侧边新面板打开（与内置一致）。
   - 长按或右键菜单：强制新建对话（保留原功能）。
   - 若面板当前已在某个对话中：点击仅聚焦回当前对话，不切换，避免误触丢上下文。

### 优化建议

- 空对话自动清理后，同步把注册表里对应的条目清掉，避免"上次对话"指向已删除块；
- 最近对话被删除/跨仓库失效时自动回落新建，并在通知里提示"上次对话已被清理，已新建"；
- 历史列表支持按"有无内容/时间/根块"筛选，与特性 2 的管理面板共用数据源；
- 给按钮加角标区分状态（如当前是否已有历史对话）。
- 二期可做"最近 5 条对话"的浮层列表，单击按钮展开选择，而不是只恢复 1 条。

## 三、特性 2：AI 对话记录管理增强（含空对话自动删除）

### 可行性：✅ 高（约 9 分/10），且收益最直接

### 1. 对话管理入口

仿 layout-manager 注入一个侧边栏 Tab（`nav#sidebar`）或注册一个块渲染器，列出当前仓库全部
`aichat` 块：

| 列 | 来源 |
| --- | --- |
| 标题 | `_repr.cap`（空则显示"未命名 + 创建时间"） |
| 消息数 / 是否空对话 | `_repr.msgs` 过滤 `role==="user"` |
| 最后活跃 | `block.modified` |
| 所属文档 | `_repr.ctx[0]` 对应根块 |

操作：打开、重命名（写 `cap`）、删除、导出（plain 转换器已有 aichat 支持）。

### 2. 空对话自动删除（核心）

**判定规则**：`_repr.type === "aichat"` 且 `msgs` 中无任何 `role === "user"` 消息。
（注意：首次渲染会写入 system 消息，不能只看数组长度。）

**推荐清理策略（分级，默认保守）**：

1. 即时标记：空对话创建后 N 小时（如 24h）内无 user 消息 → 进入候选。
2. 触发时机：应用启动 + 每天一次；后台扫描（`requestIdleCallback` 节流），避免大仓库卡顿。
3. 删除保护（必须）：
   - 不删当前面板正在展示的对话；
   - 不删有引用（`backRefs`/`children`）的对话；
   - 批量删除前给出候选数量和预览，先"清理演练"再执行；
   - 优先走 `core.editor.deleteBlocks`（可撤销）而不是裸 `delete-blocks`；
   - 可选"软删除"：先打上标记/移入归档块，确认无误后再物理删除。
4. 清理报告：删除 N 条、释放位置，用 `orca.notify` 汇总。

### 3. 管理增强建议

- **去重**：多次点击 AI 助手造成的连续空对话，按 `ctx` + 创建时间聚类，一键清理。
- **归档/导出**：将若干旧对话合并导出为 Markdown，或折叠为一个归档块。
- **自动标题**：为有内容但无 `cap` 的对话批量补标题（可复用内置的标题生成逻辑思路）。
- **跨仓库**：MVP 只管理当前仓库；二期遍历 `orca.state.dataDir` 下 repos 目录逐库处理。

改应用源码会在升级时被覆盖，且维护成本高。若"内置"指随应用分发，插件目录部署即可达到同等效果。

## 六、与 Orca Pinner 的兼容性（重点核对）

**结论：存在一个明确的冲突点，但因为两个插件都是自己维护的，可以彻底解决。**

### 1. 核心冲突：pinner 会劫持"导航到对话块"

Orca Pinner（v1.0.3，`pinAIPanels` 默认开启）在 `load()` 时执行
`installAIChatRedirect()`，**全局包装了 `orca.nav.goTo`**：

```js
nav.goTo = (view, viewArgs, panelId) => {
  if (tryRedirectAIChat(view, viewArgs)) return   // aichat 块 → 改为钉住浮窗
  origNavGoTo?.(view, viewArgs, panelId)
}
```

`tryRedirectAIChat` 的判定是：`view === "block"` 且目标是 `_repr.type === "aichat"` 的块
（与我们的对话识别方式完全一致）。也就是说：**任何代码（包括我们的插件）用
`goTo("block", {blockId: 某对话})` 打开对话时，都会被 pinner 改为在浮动钉住窗口打开**，
"在该面板内打开"的语义失效。它只放过 `openInLastPanel`（Shift 侧边打开路径）。

### 2. 次要重叠：两个插件都向面板右侧工具条加按钮

pinner 用官方 API `orca.editorSidetools.registerEditorSidetool` 加图钉按钮
（`render(rootBlockId, panelId)`）。我们的按钮也用同一 API、不同 id 注册即可共存，
这一层不构成真冲突。

### 3. 兼容方案（按推荐顺序）

| 方案 | 做法 | 效果 | 改动量 |
| --- | --- | --- | --- |
| A. 顺其自然 | 我们只负责"找到/查找对话"，打开仍走 `goTo`，交给 pinner 显示 | 点按钮 = 上次对话在钉住浮窗打开（本就是 pinner 的核心体验，多对话可分别钉住） | 零 |
| B. 按设置分流 | 读 `orca.state.plugins["orca-pinner"]?.settings?.pinAIPanels` | pinner 开 → 方案 A；关 → 正常面板内打开 | 只改我们 |
| C. 强制面板内打开 | pinner 的 `tryRedirectAIChat` 加一行豁免（如检测 `viewArgs` 上的专用标记），我们导航时带标记 | 保证"在该面板打开" | pinner 一行 + 我们传标记 |

推荐：先按 **方案 B** 实现（不改 pinner，行为自适应），若后续确定要"面板内打开"语义，再落 **方案 C**。

### 4. 实现层面注意事项

- 我们的按钮注册用 `orca.editorSidetools.registerEditorSidetool`（render 直接拿到
  `rootBlockId` 与 `panelId`，正好是注册表需要的稳定键 + 会话级细分键），**不要再用
  DOM 事件代理去碰内置 AI 按钮**，省掉与 pinner 按钮共存的 DOM 风险；
- 不要在任何 `load()` 时缓存 `orca.nav.goTo` 引用（pinner 可能在前后加载并包装/还原），
  每次点击现取现用；
- 空对话自动清理、注册表维护等不涉及导航的逻辑与 pinner 无任何交集，可并行开发。
