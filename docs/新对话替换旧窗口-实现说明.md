# 手动拉起新 AI 对话窗口(替换旧窗口)——实现说明

> 对应版本:v0.1.0。本文记录该功能的设计决策与实现细节,供后续维护与二期功能(面板历史、对话管理)复用。

## 一、需求

内置的 AI 按钮每次点击都会**新建**一个空 `aichat` 块并跳转,但没有"替换"语义:
旧对话窗口仍在,且容易积累无内容的空对话。本功能提供明确的**手动**动作:

> 点一下,在当前面板拉起一个全新的 AI 对话窗口,替换掉旧的对话窗口。

## 二、交互设计

在块编辑器右侧工具条(`.orca-block-editor-sidetools`,官方 `orca.editorSidetools` 通道)新增
「新对话」按钮(AI 图标带橙色 `+` 角标,与内置 AI 按钮区分):

| 操作 | 行为 |
| --- | --- |
| 单击 | 新建空 `aichat` 块(沿用旧对话 `ctx`),在**当前面板**替换旧视图;旧对话仍保留在文档中,可用面板「返回」找回 |
| Shift + 单击 | 与内置一致,在侧边新面板打开 |
| 当前对话已有用户消息 | 先弹确认框,防误触 |

按钮默认仅在「当前面板显示 AI 对话」时出现(可关,改为所有面板常驻)。

## 三、关键技术决策

### 1. 新建对话:完全复刻内置 AI 按钮的调用

内置 AI 按钮回调(渲染包 `index-BXaynqXZ.js` 实测):

```js
await orca.commands.invokeGroup(async () => {
  j0 = await orca.commands.invokeEditorCommand(
    "core.editor.insertBlock", null, null, null, null,
    { type: "aichat", ctx: [当前根块], msgs: [] },
  )
  await orca.commands.invokeEditorCommand("core.editor.insertTag", null, j0, AI标签)
})
goTo("block", { blockId: j0 })   // Shift → openInLastPanel
```

本插件完全复用该调用(anchor/position 均为 `null`,新块创建在库顶层);
差异仅在 `ctx`:**当前视图已是对话时沿用旧对话的 `ctx`**,保证新窗口继承同一文档上下文。

### 2. 替换旧窗口:手动复刻内置 `goTo` 的面板内替换逻辑

Orca Pinner 会全局包装 `orca.nav.goTo`,把"导航到 aichat 块"改为浮动钉住窗口,
这会破坏"在当前面板替换"的语义。因此本功能不依赖 `goTo`,而是复刻应用内置
`goTo` 的内部逻辑(对照渲染包确认):

```js
// 内置 goTo 的核心(压缩源码,节选)
const Ji = findViewPanel(pr, panels)
if (Ji) {
  if (Ji.locked) { openInLastPanel(...); return }
  Ji.view === view && equals(Ji.viewArgs, args) ||
  (pushBackHistory(当前面板状态),
   Ji.view = view,
   Ji.viewArgs = args,
   Ji.viewState?.editor && (Ji.viewState.editor.showMindMap = false),
   clearForwardHistory())
}
```

本插件直接修改面板的 `view` / `viewArgs` 并手动维护 `panelBackHistory` / `panelForwardHistory`,
行为与内置一致且不触发任何 `goTo` 包装:

- 替换后旧对话保留在面板返回历史中,可「返回」找回;
- 面板锁定(如 AI 面板被锁定)时按内置语义改为侧边新面板打开;
- 新对话块与内置打开路径完全一致(`BlockPanel` → `BlockEditor` → aichat 渲染器),无特殊渲染分支。

### 3. 其他实现细节

- **设置键**:对照渲染包 `AppKeys`:`AIBaseURL=19`、`AIAPIKey=20`、`AITag=21`、`AIModel=22`,
  与内置 AI 按钮读取的一致;
- **对话判定**:`_repr.type === "aichat"`;镜像块通过 `mirroredId` 解出真实块;
- **"有内容"判定**:`msgs` 中存在 `role === "user"` 的消息(与可行性分析中的空对话判定一致);
- **按钮渲染**:`orca.editorSidetools.registerEditorSidetool`,render 签名
  `(rootBlockId, panelId)`,按需返回 `null` 隐藏按钮;UI 用 `window.React.createElement`
  与 `orca.components.Button / Tooltip`,与 Orca Pinner 同模式,无 DOM 注入、无需样式表;
- **未配置 AI 时**:提示并带「打开设置」action,与内置行为一致。

## 四、与 Orca Pinner 的兼容性结论

- 本功能的「替换」动作不调用 `goTo`,因此 **pinner 的浮动钉住不受影响也不会破坏替换语义**;
- 其余路径(如 Shift 侧边打开)仍走 `goTo` / `openInLastPanel`,交给 pinner 处理;
- 若后续要支持 pinner 的钉住浮窗打开新对话,可在设置中增加分流选项,无需改动 pinner。

## 五、后续可扩展

- 与 F1(面板对话历史)共用数据源:替换动作同步登记「面板 → 对话历史」注册表;
- 与 F2(空对话清理)联动:替换产生的旧空对话可纳入自动清理候选;
- 可加「替换后是否删除旧空对话」的可选行为(需确认保护,默认不删)。
